# 复杂任务呈现重设计：让对话流里每一句话都属于模型

> 状态：设计稿（2026-10-06）。
> 触发：用户两次反馈合并——① pure 在复杂/多步规划任务上不如 Claude Code（呈现、规划合理性、处理合理性、步骤清晰、拟人度、怎么做的/做了什么/结果如何），要求改彻底；② **补充定调**：长程任务的呈现「完全没逻辑，固定输出语句、固定话术，还啰嗦，完全没有智能的体现，没有怎么思考的这些内容」。
> 定位：与 [`conversational-intelligence-upgrade.md`](conversational-intelligence-upgrade.md)（对话蓝图）**不分治**——那份管「信号的即时性/可达性/持久性 + 账本/调度/预期」（父子边界与实时对齐）；本文管**「呈现：谁在说话、说什么、怎么把结构讲清楚」**。两文都读。

---

## 1. 用户判据（可回放）

| # | 抱怨轴 | 判据（回放时应看到的） |
|---|---|---|
| J1 | 呈现没有逻辑 | 对话流读起来是一条因果链：为什么这么做 → 做了什么 → 结果如何 → 下一步为什么。不是一串互不相干的固定状态句。 |
| J2 | 固定输出语句 / 固定话术 | 同一类事件在不同任务里，**措辞由模型按当下语境产出**，不是同一句模板换个参数。 |
| J3 | 啰嗦 | 只在高价值节点说话；机械噪音（排期、轮次、emoji 状态腔）不出现在对话流。 |
| J4 | 没有智能的体现 / 没有怎么思考 | 看得见模型**当场的判断与权衡**（不只是「正在处理」），且这些判断由模型自己说。 |
| J5 | 步骤清晰 / 做了什么 / 结果如何 | 每一步的产出与证据可查、可对照承诺（`expectedOutcome`）。 |
| J6 | 规划与处理的合理性 | 计划是当场想出来的（已实现 `planByThinking`）；失败改方向不重试；不确定不包装成完成。 |

## 2. 现状锚点与证据

**已具备的资产（复用，不重造）**
- 规划来自模型流式思考 + 末尾 ```json 步骤清单：`src/ui/planNarration.ts` + `chat.ts:planByThinking()`。思考**已经当着用户流式展示**。
- 思考卡：`src/ui/thinkingCard.ts`——推理流默认展开、可折叠、带耗时与慢响应提示。**「怎么思考」的载体已经存在。**
- 计划步骤结构化字段：`action / description / expectedOutcome / substeps / todosRequired`（`src/coding-agent/types.ts:37,44`）。
- 进度状态机 `PlanProgressModel`（`src/ui/planProgress.ts`）从控制行推进，含漏标记兜底。
- 工具行像 Claude Code（`src/ui/toolRow.ts`）；快照持久化 + 重放（`store.ts` / `transcriptProjection.ts`），「实时=重载」已成立。

**病灶证据（这就是「固定话术」的产地）**
- `chat.ts` 里约 **40 处 `addStatusBubble`** 直接以 agent 口吻写死整句：
  - `'收到——看一下这句话怎么安排…'`（chat.ts:2588）
  - `'📋 已建立任务契约：N 项验收标准，验证结果将决定是否交付。'`（:4706）
  - `'🛠️ 修复阶段：agent 正在根据真实失败输出修复并重新验证…'`（:5310）
  - `'🔁 第 N 轮修复完成，重新执行全部交付验证…'`（:6177）
  - `'收到，接着第 N 阶段的第 M 个 Todo 往下干。'`（:5099）
  - `'这句补得关键——推倒刚才想的，带着它重新想一遍。'`（:4858）
- 进度播报是纯模板：`plan.narrate.advance1/advance/done/done1`（`i18n.ts:1095-1099`、`planProgress.ts:277`）——「前 N 步都完成了，正在跑第 M 步。」
- 复杂任务开场是固定句：`planSummary.ts:51-52`——「这个问题不简单，我让…分头处理，最后我来汇总结果给你。」

这些行**全部由 host 生产、以 agent 口吻发出**，措辞不随任务变化 → 用户读到的就是模板腔与啰嗦，而模型自己的判断被挤到折叠卡里。

## 3. 根因

**根本病灶：host 在替模型说话。**
1. **越权代述**：host 用固定字符串冒充 agent 的语气。模型即便想得再清楚，屏幕上最显眼的仍是 host 的模板句。→ J2/J4 直接受损。
2. **只报状态不报因果**：host 的话术只有「发生了什么机制」（已排期/正在修复/第 N 轮），没有「为什么、所以呢」。→ J1 受损。
3. **喧宾夺主**：真正有智能的内容（思考流、判断）在折叠卡与模型正文里，被 40 句状态腔稀释。→ J3/J4 受损。

这与此前已记录的教训同源（`改进进度记录.md`：「提示词里每一条『必须先说 X 再说 Y』都是写死模式的种子」）。**现在要补的是：host 里每一句写死的『人话』，都是固定话术的种子。**

## 4. 铁律（本设计的核心不变式）

1. **对话流里以 agent 口吻出现的句子，只能来自模型。** host 不得生产以 agent 语气发出的句子。
2. **host 只允许产出两类东西**：①**结构化事实/状态**（非散文，机器可读，供 UI 渲染）；②**系统机制通知**（暂停/错误/需要你操作——这不是 agent 在"说话"，是系统状态，必须与 agent 口吻在视觉上明确区分，且极简、无 emoji 装饰、无模板腔）。
3. **机器噪音不进对话流**：排期、轮次计数、机制进程这类，进状态区/卡片，不进消息正文。
4. **思考要可见**：模型在"有意义的节点"用自己的话讲判断（沿用 COMPLEX_TASK_PROTOCOL「Speak at meaningful nodes only」），host 负责把噪音清干净好让这些话说得出来。
5. **实时=重载、防缠三原则、控制行解析器**：不破。结构化进度仍是唯一产物；控制行字面量在期 3 前零改动。

## 5. 目标设计：三层

### 5.1 结构层 —— TaskScript（承接 J5）
沿用本文件上一版的核心：`src/shared/taskScript.ts`，让**步骤状态与产出由运行时从真实信号推导并记账**（control-line / tool / verification / turn-end / branch 多信号合流），计划卡、步骤条、收尾素材都从这一份剧本派生。意义：让「每步做了什么、结果如何」有账，**但这本账只供给模型当素材与 UI 当结构，不自己拼成句子**。

### 5.2 叙事层 —— 话归模型（承接 J1/J2/J4）
- **删掉 host 的 agent 口吻句**：`formatPlanProgressNarration` 之类的「进度人话」不再由 host 生成，改为 ① 结构化进度进计划卡（无 prose），② 需要开口时由**模型在回合内**用当下语境说。
- **降级 `/ 去噪` 系统通知**：暂停、错误、需要用户操作等保留为**极简系统行**（去掉 emoji 装饰与模板腔），与 agent 正文视觉区分。
- **思考可见**：思考卡保留并作为主叙事载体之一；`planByThinking` 的思考流继续当着用户看。
- **收尾**：`COMPLETION_LESSON_PROMPT` 的「依据/改动/验证/遗留」四点由模型用自己的话讲，TaskScript 只把**事实**喂给它（改了什么文件、跑了什么、结果），模板与句式不注入。

### 5.3 协议层 —— 只规定实质（承接 J3/J6）
- 强化「在真正的节点才说话、说自己的话、不复述机制」，**不新增任何句式模板**。
- 新增 1 条实质约束：一步真正完成时，用一句人话说清这一步**交付了什么、你怎么验证的**；失败直说。带内容锁测试，且**不引原句**（防八股）。
- 控制行从「必须发」降为「发了更准」（期 3，单独立项评审；解析器保留）。

## 6. 分期落地（每期独立可发布 + 可验收）

| 期 | 内容 | 验收 | 量级 |
|---|---|---|---|
| **期 1 · 呈现去话术**（先打，直击用户痛点） | 清点 `addStatusBubble` 全量，二分类：**agent 口吻句**（删/改由模型说）vs **系统机制通知**（保留但极简、去 emoji、去模板腔）；`formatPlanProgressNarration` 的固定人话下线，进度回到结构化呈现；`planSummary` 固定开场句下线。 | UI 单测 + 回放判例：同一任务不出现固定模板句；系统行与正文视觉可分；实时=重载不破 | 中 |
| **期 2 · 结构账** | `src/shared/taskScript.ts` 纯函数（进度/产出/证据多信号合流）+ 计划卡步骤条读剧本；收尾素材从剧本汇总给模型 | 纯函数单测 + 漏控制行时工具信号兜底判例 | 中 |
| **期 3 · 协议升级** | 控制行降为可选信号（单独立项）；新增「每步收尾一句实质」+ 内容锁 | 内容锁 + 全量回放不回归 | 中 |
| **期 4 · 父子与持久** | 子代理 `branchOutcome` 回灌步骤产出；TaskScript 进快照升版 | 子代理完成→父步骤产出入账；重启后剧本一致 | 中 |

**期 1 是本次用户痛点的正面回答**，优先做；期 2 为「结果如何」提供账；期 3/4 收口协议与父子。

## 7. 风险与取舍

| 风险 | 对策 |
|---|---|
| 期 1 删/改 40 处 status 行 → 回放保真与既有测试大面积回归 | status 行已入账（`StatusLineRecord`），**只改文本与呈现，不动入账/锚点机制**；分批改，每批跑 `sessionReplayFidelity` 与相关回放 |
| 「进度回结构化」被理解成退回被否决的顶部进度条 | 明确：**不是加绳子，是撤掉替模型说的嘴**。进度用计划卡已有结构呈现，不新增 bar 语汇 |
| 系统机制通知与 agent 正文混淆 | 给系统行独立视觉语言（灰、无 emoji、固定前缀空间最小化），判例里对照 |
| 期 3 动控制行破坏既有回放 | 单独立项评审；解析器零改动；「发了更准」语义 + 对照回放 |
| 与对话蓝图第 4 期（SessionLedger）重叠 | SessionLedger 管跨轮去重；TaskScript 管本计划步骤的结构与产出；共享存储不互相吞并 |

## 8. 被放弃的方案（记录取舍）

- ❌「把 host 话术写得更自然」：写得更顺的模板仍是模板，J2 不变。
- ❌「加更多状态行解释步骤」：与 J3（啰嗦）冲突；问题不是信息不够，是**噪音盖过模型**。
- ❌「退回固定步骤列表」：用户已否决（`改进进度记录.md`）；规划来源不动。
- ❌「再起一套进度系统」：违反防缠三原则；必须是收束现有表面，不是新增第五个。
