# 自我进化系统设计

> 2026-09-18，红队评审后定稿（v2）。目标：让 pure 在使用中**减少错误、提高效率、贴近用户**——错误及时变成修正，重复任务变成套路，输出越来越像用户自己想要的。
>
> 设计原则一句话：**不另起炉灶**。pure 已有一套完整的记忆基建（读写闭环、健康分生命周期、注入通道、设置面板），进化系统 = 在它上面补齐缺失的三层——**提炼**（把经历变成教训）、**度量**（证明教训有用）、**回调**（教训反过来改行为）。现状是"记住了但不变好"。
>
> 评审记录：红队核验 17 处现状断言、2 条 blocker 已修（Completed 非 HookRouter 事件、便宜模型通道依赖）、多条量级与顺序已按证据修正。

### 1.2 缺口清单（本设计要填的坑）

1. **FailurePolicy 跨会话零学习**：无状态阶梯（重复 2 次 reflect / 3-4 degrade / ≥5 stop，FailurePolicy.ts:44-59），同样的坑每个新会话从零踩一遍。
2. **lesson 是字符串拼接不是提炼**：error_pattern 的 rootCause 就是"错误消息拼接"，无 LLM 参与写记忆。
3. **adaptiveControl 无反馈环**：策略现算、效果从不度量；confidence 是常数公式。
4. **`project_convention` 是死类型**：类型定义、权重、UI 都有，全库零写入点。
5. **经验→技能无自动化**：高频 procedure 永远不会变成 SKILL.md。
6. **观测只写不读**：产品内没有任何分析回路，且 2000 条轮转撑不起时间窗口统计。
7. **评测不带记忆**：进化效果无法度量。
8. **GUI 跨会话丢上下文**：会话恢复只还愿 UI；摘要从不写回记忆库。
9. **记忆无机械约束力**：error_pattern 只以文本进 prompt，学习效果全押在模型服从性上。

### 1.3 设计立场：三条纪律

1. **每个学习回路必须带度量，否则不发布。** 没有尺子的进化是自我感觉良好。
2. **软引导优先，硬门禁白名单制。** 经验默认以文本进 prompt 引导模型；只有用户明确开启的少数规则才允许机械拦截。
3. **用户可见可控。** 一切学习产物落记忆库，可看、可删、可导出；进化永远可以被关掉（Settings 一个总开关）。

## 2. 总体架构：四层进化环

```
        ┌─────────────────────────────────────────────────┐
        │                                                 │
        ▼                                                 │
  ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
  │ ① 感知   │──▶│ ② 提炼   │──▶│ ③ 注入   │──▶│ ④ 度量   │
  │ Observa- │   │ Distill  │   │ Inject   │   │ Measure  │
  └──────────┘   └──────────┘   └──────────┘   └──────────┘
```

- **① 感知**（已有，补持久化）：promptObservability 打点 → JSONL 默认落盘（**聚合写或提高上限**，2000 条轮转撑不住时间窗统计）。
- **② 提炼**（本设计主体）：turn 后反思器 + 蒸馏触发器，产出结构化经验，全部走既有 `IMemoryStore`。**新增 MemoryType 的真实改动面**：检索/衰减免费；注入需扩 Harness 分组映射 + PromptAssembler 的 PromptMemoryContext；取代需扩 SUPERSEDABLE_TYPES 白名单 + comparisonText 模板 + CREDIBILITY 权重。能用现有类型的绝不新增。
- **③ 注入**（已有，一条缓存共存决策）：见下方 §2.1。
- **④ 度量**（新增）：评测 A/B（带记忆 vs 不带）+ 运行时指标。度量结果反哺健康分——**没用的经验加速遗忘**。

### 2.1 缓存共存决策（前置条件，所有注入类改动受此约束）

8.2 的缓存断点假设 system prompt "identical every turn"；而 composeMemoryPrompt 每次 continueTurn 用新追问重搜记忆、重写 `<session_memory>`——缓存已经被现有逻辑打穿。E2/E3 的动态注入会放大这个问题。决策：

1. **会话内冻结**：`<session_memory>` 只在会话首轮 run() 检索注入一次，continueTurn 不再刷新 system prompt 的记忆区——经验是慢变量，会话中途学到的东西本来也不该改身份层。
2. **会话中途的新教训走既有 FailurePolicy hint 通道**（引擎内 user 消息注入，不在 system prompt，不碰缓存）——这条通道今天已经存在。
3. 该决策作为 E0.2 的一个验收点实现并测试（缓存命中不被记忆注入打穿）。

数据流一句话：**打点 → 反思/蒸馏 → 记忆库 → 注入通道（会话内冻结）→ 下次会话行为变化 → 指标变化 → 反哺健康分与仪表盘**。

## 3. 三维度设计

### 3.1 减少错误：从"记下错误"到"改正出错的东西"

#### E1.2 FailurePolicy 跨会话经验加速（先做——纯管道，零 LLM 成本）

- **机制**：会话启动时从记忆库预载**同步快照** `FailureHistory`（同工具+同错误分类的历史重复次数，聚合一次数据库查询，decide() 保持同步签名），历史已见过的坑**阶梯起点前移**：首次即 reflect（附历史教训文本），2 次即 degrade；新坑照旧 2/3/5。
- **复用**：现有 error_pattern 字符串记忆即可支撑（无需反思器先行）；FailurePolicy 构造注入 `FailureHistory` 接口，核心保持无状态可测。
- **边界**：只影响提示强度与跳过时机，不做硬拦截（纪律 2）。

#### E1.1 turn 后反思器（Lesson Reflector）

- **机制**：Completed 后，若本轮满足触发条件（有失败、或非平凡多步过程），用**便宜快模型**（依赖 E0.3 的按阶段 adapter，见 §5）跑一次结构化反思，产出 lesson 条目：`symptom / rootCause / prevention / evidence(工具调用哈希引用) / scope`。替换 writeSessionMemory 的模板拼接——模板版保留为反思器失败的兜底。**fire-and-forget**：反思不阻塞回合收尾，下一轮会话开始前完成即可。
- **挂载点**：Harness 现有 Completed 消费路径（writeSessionMemory 同址，Harness.ts:413、605）——**不是 HookRouter**（引擎 7 钩子无 Completed 事件，ctx 也没有反思器需要的结局/失败/记忆句柄；HookRouter 留给未来的阶段级干预）。
- **防幻觉纪律**：反思输出必须引用本轮真实工具调用（evidence 哈希），无证据的根因猜测打 `confidence: low` 且默认不注入。
- **成本护栏**：每日反思次数上限（默认 20）；触发条件门控；可单独关闭。

#### E1.3 工具/服务级自修正建议

- **机制**：观测数据里同一工具+同一错误分类聚集成簇（N 天内 ≥ 阈值）→ 产出**工具修正建议**：a) 工具使用注意写进记忆（复用 `tool_preference` 类型，注入 tools 段）；b) 达阈值时设置页工具卡提示。不自动改 toolDefs 代码——建议给用户，点头才落库。
- **复用**：错误分类已有（netGuard classifyFailure）；扫描器复用 memoryDecayTimer 的空闲调度模式。

#### E1.4 子代理配置自校正（后置，依赖 E4.1 per-role 指标）

- **机制**：度量显示某子代理角色持续超时/被 watchdog 误杀/产出常被重做 → 出调整建议卡片。第一版只建议不自动改。

### 3.2 提高效率：从"每次重新想"到"轻车熟路"

#### E2.1 playbook：复用 procedure 类型，不新增

- **机制**：反思器在**成功完成的多步任务**上额外提炼步骤序列（意图 → 步骤骨架 → 验证方式），以 `procedure` 类型落库（≤600 字符）——procedure 已在取代白名单、已有注入段（priority 40）、检索/衰减全通，**零新类型成本**。下次高相似任务检索命中即注入，附"上次同类任务 N 步完成"。
- **效率度量**：multi-step fixture 带记忆 vs 不带的步数对比（E0.2 的直接产出）。

#### E2.2 经验→技能沉淀（第一版用户触发）

- **机制**：对话里加一条**用户指令**（如"把这个做法沉淀成技能"）：取最近命中的 procedure/playbook，让模型扩写成标准 SKILL.md，落 `~/.pure/skills/auto-<name>/`，设置页出现新技能卡（可一键删）。**不做自动触发**——"使用后成功"的归因度量目前不存在（hitCount 只反映检索命中），等 E4.1 有归因数据后再评估自动阈值。
- **复用**：parseSkillMarkdown / `<skills>` 注入全不动。

#### E2.3 计划层并行标注

- **机制**：adaptiveControl 已输出 `parallelRoles`（per-request 粒度），把它接进计划卡片：计划步骤标"可并行"标记，批准后 SubagentOrchestrator 按标记组批。**收益边界如实说**：独立只读子代理今天已能并行（reads 并发池），真实增量是"计划层把串行步骤识别为可并行"的那部分墙钟时间。

### 3.3 增强体验：搭反思器的便车（不设独立节奏）

> 红队结论：E3 单独立阶段的 ROI 是三个维度里最差的，降级为反思器的顺带产出。

- **convention 收割**（砍掉 AGENTS.md 镜像——约定已通过 `<project_conventions>` 片段 required 级必达模型，镜像纯冗余）：反思器识别"用户纠正过输出风格/做法/项目规矩" → 写 `project_convention`/`user_preference` **草稿**（confidence: low，进仪表盘待确认，确认后才有注入资格）。
- **偏好画像**：正则收割层（现有，零成本）保留；LLM 层就是反思器的顺带产出，不设独立的"每 N turn 检查"。
- **输出生效**：确认后的偏好经既有 preferences 注入段 + delivery 层生效，无新代码——验收并入上两条。

## 6. 风险与安全阀

| 风险 | 对策 |
|---|---|
| 经验污染（错误教训自我强化） | lesson 必须带证据哈希；无证据默认不注入；健康分让未使用的低质经验消亡；取代链保证新正确覆盖旧错误 |
| 反思器烧钱 | 便宜模型（E0.3）+ 触发门控 + 每日上限 20 + fire-and-forget 不阻塞；可单独关闭 |
| 提示词膨胀挤占窗口 | 全部走既有片段优先级与预算裁剪；会话内冻结不再增加每轮注入 |
| **缓存断点被打穿** | §2.1 冻结决策是所有注入类步骤的前置条件，E0.2 带验收测试 |
| 隐私 | 一切本地（~/.pure），零外发；收割只在本地正则+本地/自选模型 |
| 用户失控感 | 总开关 + 记忆仪表盘 + 技能一键删；自动行为可降级为"每次询问"；技能沉淀第一版就是用户触发 |
| 过拟合 eval | A/B 看步数/耗时/重试的结构变化而非只看分；procedure 命中要求相似度阈值 |

## 7. 与现有路线图的关系

- 本设计是 2026-09-17 优先级决定（智能化/自动化/效率）的**系统化展开**；**原路线图 9.1（按阶段模型路由）前移为 E0.3**，其余旧路线（6.4 OAuth）与 E 阶段可交错，同一时间仍只开一个步骤。
- 红队评审已驳回的点（留档防止回潮）：把反思器挂 HookRouter（Completed 不是其事件）、AGENTS.md 镜像进记忆（与 required 片段冗余）、技能自动蒸馏提前（无归因度量）、playbook 新类型（procedure 白名单已覆盖）。
