# pure 团队可观测（北极星第 6 步）设计

状态：**方案定稿（2026-09-22），未实施**。上游定调见
`docs/multi-agent-self-evolving-architecture.md`（团队可观测在分期路线第六步，
定位「自生长 + 看得住」中的“看得住”）；13.3 part 3 试用期间的真实数据盘点
（2026-09-22）直接催生了本设计——观测数据的缺口不只是"页面缺几张图"，
而是**进化闭环的地基有洞**。

## 0. 为什么现在设计它（盘点暴露的四个数据缺口）

2026-09-22 对本机 E4.1 观测（`~/.pure/observations/app.jsonl`）与会话存档的
交叉盘点结论：

| # | 发现 | 后果 |
|---|---|---|
| G1 | **委派只有统计，没有身份**：`AgentRunObservation.toolCalls` 里的角色委派是匿名条目（`toolName` = 角色名），没有 `ag-xxxxxxxx` 运行 id、没有逐调用 `startedAt`、没有委派级 token/产出规模 | 无法回答"这次委派慢在哪、贵在哪、产出是什么"，ag-id（运行时早已有）在观测层断链 |
| G2 | **观测与存档只能靠猜配对**：`agent_run.sessionId` 虽然就是存档目录名（2026-09-22 MVP 设计时核实），但收割器并不知道这层对应，仍按角色名+args 语义猜配对；且会话一旦删除（G3）配对永远失败 | 观测说有 40 次委派，收割 raw 只剩 17 条（去重后 15）；归因靠猜测 |
| G3 | **存档一删，历史观测变孤儿**：10 个有委派的会话目录已被删除（无自动清理策略，系试用期间手动删除），对应 30 次委派永久不可收割、不可回放 | 13.1/13.3 的 A/B 样本量被腰斩（researcher 30 → 4）；"删除会话"这个用户动作有一个没人告诉他的隐性代价 |
| G4 | **成本只有父任务视角**：`usage` 是整轮聚合；团队维度（每角色、每模型、每 provider 的花费占比）不存在 | "这支团队贵在哪"没有数据，13.4 工具固化与按阶段模型路由（9.3）的效果无处度量 |

G3 是最疼的一个：它把"看得住"变成了"看得住的窗口只有会话活着的时候"。

## 1. 定位与不变量

**团队可观测 = 观测层→UI 的一条只读读模型**。它不产生任何运行时行为，不做任何
进化动作——那是 E1.4 / 13.3 的地盘。因此它天然满足北极星三条防缠原则：

- **原则二（观测单向）**：只读 `~/.pure/observations/app.jsonl` 与会话存档，
  运行时零改动（观测 schema 的增补字段除外，见 §3）。
- **原则三（事件即接口）**：所有新维度都从既有事件流推导，不新增子系统间调用。
- **反面清单第 3 条**：可观测不准入任何东西。它产出的是"看"，不是"判"；
  A/B 门槛（13.3 part 2）裁决时继续用自己的回归报告，不读这里的任何结论。

**红线**：v5 基线不倒退；全量测试绿；观测开关关掉后运行时行为逐字节不变
（E0.1 既有契约，`enabled:false` 时连记录都不写，本设计全部字段随行）。

## 2. 用户问题 → 页面 → 数据源

团队可观测在设置页「进化」区新增一个**团队切片**（独立卡片区，复用 `evo-table`
/ `evo-stat-note` 视觉语言），回答四类问题：

| 用户问题 | 页面呈现 | 数据源 |
|---|---|---|
| "我的团队都有谁、最近被用得多吗" | **角色阵容表**：每角色行——30 天派发数、成功率、平均耗时、token/成本占比、是否带 overlay、样本存量（`~/.pure/roles/<role>/` case 数 vs `MIN_ROLE_CASES`） | agent_run 切片 + roles 目录扫描（Rust IO，TS 只读清单） |
| "每个角色实际在做什么" | 点角色行展开**委派明细**，可跳回会话看完整产出 | G2 修复后：observation 存 `sessionRef`，Rust 按需读单会话存档抽产出（读模型，不入库） |
| "这次派发为什么慢/贵/失败" | **单次委派详情**：ag-id、时长、token、产出 chars、错误类、所属会话 | G1 修复后的 delegation 明细 |
| "这支团队贵在哪" | **成本视图**：按角色 × provider/model 的成本占比表（记住三 provider 格局） | G4 修复后的 delegation usage |
| "团队最近哪里在反复掉链子" | （已有）E1.4 建议卡 + E4.2 错误簇——本设计**不重做**，只保证数据源修复后它们读得更准 | 现状 |

> 阵容表的"样本存量"列是 13.1/13.3 的**望楼**：门为什么关着（<5）、差几条、
> 该往哪派发补样本——这一列把 2026-09-22 盘点结论变成常驻可见的状态。

## 3. 数据层补缺（先修管道，再装仪表）

页面的每一列都卡在 §0 的缺口上，所以数据层先行，且**全部是观测 schema 的增量
字段**（`schemaVersion` 不动——parser 对未知字段宽容，旧记录缺字段自然留空）：

### 3.1 G1：委派身份与成本下放到观测（TS 侧，M）

`AgentRunObservation` 新增 `delegations: DelegationObservation[]`（与 `toolCalls`
并存——`toolCalls` 语义不动，E4.2 既有聚合器零改动）：

```ts
interface DelegationObservation {
  agentId: string;          // ag-xxxxxxxx（运行时已有，今天没写进观测）
  role: string;
  startedAt: number;        // 委派粒度时间戳
  durationMs?: number;      // 结束时补
  success?: boolean;        // 结束时补
  tokensUsed?: number;      // SubagentResult.tokensUsed 已有
  outputChars?: number;     // SubagentResult.output 规模（只记 chars，不记文本）
  errorKind?: string;       // 复用 errorKind() 分类
  relayConsumedBy?: string[]; // 接力下游；T4 评估接线，一期缺省
}
```

来源：`CodingAgent.publish()` 已在转发 `SubagentActivityEvent`（`onDone` 的
`SubagentActivity` 带 agentId / duration），`SubagentResult` 带 tokensUsed——
编排点在 `CodingAgent` 把这两处已有的数据写进当前 `agent_run` 记录即可。
引擎主循环零改动；orchestrator/结果类型只加**可选字段**（§3.4 的 usage 拆分），
不碰执行路径。`relayConsumedBy` 一期可缺省——relay 收据在协调器里，接线随
T4 链路图一起评估，不为它提前开跨层通道。

### 3.2 G2：收割按 sessionId 精确配对（TS 侧，S）

`agent_run.sessionId` 的取值就是会话存档目录名（`~/.pure/sessions/<sessionId>/`）
——观测与存档本来就共享同一个 id，不需要新增字段。收割器（`roleSampleHarvest.ts`）
改为优先按观测记录里的 `sessionId` 定位存档目录，全目录扫描退化为兜底；观测与
存档从此互查，13.1/13.3 的样本配对从"按 args 语义猜"变成"按 id 精确配对"。
（初版设计在此提议过 `sessionRef` 新字段——冗余，已在收官 MVP 勘误中撤回。）

### 3.3 G3：会话删除的隐性代价显性化（GUI 侧，M）

两件事，都不拦用户：

1. **删除确认卡加一行提示**（i18n zh/en）：该会话包含 N 条角色委派存档、其中
   M 条已被收割固化（`~/.pure/roles/`），删除后这些历史不可再收割。N 由
   Rust 只读命令统计，M 由 case 文件 description 里的 session 引用尽力匹配
   （匹配不上就只报 N，不假装精确）。
2. **收割"落袋为安"常态化**：阵容表样本存量列旁常驻「收割」入口（干跑 → 展示
   每角色差多少 → 用户确认才正式跑），让"删除会话"发生前样本已固化。这是把
   2026-09-22 盘点的手工动作产品化，不新增任何自动写盘。

删除统计走一个 Rust 只读命令 `summarize_session_delegations(session_id)`：
读单份存档统计 `{delegationCount, byRole}`，给确认卡用；不做任何拦截。

### 3.4 G4：成本下放与占比视图（依赖 3.1，M）

`SubagentResult.tokensUsed` 是**总量**，按 usage.ts 价目表计价需要输入/输出/缓存
拆分——总量配单价是瞎算。所以 `SubagentResult` 加可选 `usage?: TokenUsage`（从
子代理引擎自己的 Completed payload 抄过来，加法式字段、旧结果不受影响），
`DelegationObservation` 相应记 `usage?: TokenUsage` + `costUsd?: number`：
拆分 × 价目表（复用 E4.1 同款口径；未定价显示「未定价」而非 0——同一把尺子，
13.3 part 2 的教训直接复用）。成本视图按 角色 × provider × model 聚合占比。

### 3.5 观测侧留一个专用读模型（TS，S）

新 `src/shared/teamObservability.ts` 纯函数聚合器（E4.2 的 `evolutionDashboard.ts`
同款纪律：只读纯函数、可单测）：输入 `PromptObservation[]` + roles 目录清单 +
sessions 目录清单，输出阵容表/成本视图/详情所需切片。观测数据缺字段（旧记录）
或未定价时对应列显示「无数据」/「未定价」，**不冒充 0**——13.3 part 2 的同一把尺子。

## 4. UI 层（数据层落地后，M）

- 设置页「进化」区新增**团队卡**：阵容表（§2 全列 + overlay 徽章 + 样本存量列），
  点角色行展开委派明细（ag-id 可点击复制，与会话侧栏短 id 同款交互）。
- 成本视图卡：角色 × provider 占比表 + 30 天趋势点（复用 E4.2 趋势视觉）。
- 删除确认卡加 §3.3 的提示行；收割干跑预览态用 `evo-stat-note`。
- 全部文案 i18n zh/en；观测不可用（浏览器模式/读失败）时沿用 E4.2 既有空态
  语义：`available:false` → 团队卡显示空态文案（"桌面版才有观测数据"），
  不渲染表格本体——不新造一套"整体消失"的行为。

## 5. 分期（每步独立提交，可回滚）

| 期 | 内容 | 量级 | 验收 |
|---|---|---|---|
| **T1** | §3.1 + §3.2（delegations 数组进观测；收割器按 sessionId 精确配对） | M | mock provider 集成测试断言 delegations 落盘且带 ag-id；parser 兼容旧记录（缺字段留空不报错）；真机验证留待有 key |
| **T2** | §3.3（删除提示 + 收割常驻入口）+ Rust 统计命令 | M | 删除含委派存档的会话时确认卡出现统计行；收割干跑预览可取消 |
| **T3** | §3.4 + §3.5 + §4（成本下放、聚合器、团队卡 + 成本卡） | M | 聚合器单测覆盖"缺字段=无数据"口径；e2e 注入 feed 驱动团队卡渲染 |
| **T4（可选）** | 委派链路图（relay 拓扑可视化） | M | 仅在 T1–T3 落地后评估是否值得做；反面清单：不做实时协作图，只画已发生的 relay 收据 |

T1 是 13.1/13.3 的**样本望楼**与收割配对修复的前置；T3 落地后，"团队贵在哪、
谁在反复掉链子、门还差几条样本"三个问题在设置页一屏可答。

## 6. 明确不做（反面清单）

1. **不做实时协作图 / agent 间消息流可视化**：北极星反面清单第 1 条的重申——
   观测页面画"已发生的 relay 收据"可以，画"运行中的自由对话网"不行。
2. **不做运行中热载统计**：所有切片基于已落盘记录，不追加任何运行中写点。
3. **不做告警/自动干预**：可观测产出"看"，不产出"判"；阈值建议仍归 E1.4，
   准入裁决仍归 13.3 门槛。
4. **不做第二份持久化**：不建数据库、不复制观测日志；一切读模型直接吃
   app.jsonl 尾巴读 + 声明式目录。观测日志轮转（E0.1 的 64MB 门控 + 5 万条
   上限）是既有行为，本设计不新增留存策略——**但 T2 的收割落袋为安把
   "会话删了样本还在"变成常态**，留存焦虑由产物层（case 文件）承接。
5. **不新增全量扫描成本**：Rust 侧只做尾巴读与按需单会话读；阵容表的
   roles/sessions 清单是目录名枚举（廉价），不逐文件解析。

## 7. 验收口径（架构层）

1. **加一种视图的成本**：只写聚合器纯函数 + 渲染函数，运行时与数据层零改动。
2. **观测 schema 演进**：增量字段 + parser 宽容；旧记录可读、缺列显示"无数据"。
3. **回归红线**：v5 基线不倒退；全量测试绿；观测开关关闭时无 delegations 写入、
   运行时行为不变。
4. **闭环贡献**：T1 落地后，收割器能对"存档还在的会话"按 id 100% 精确配对
   （对照 2026-09-22 盘点：25/25 配对基线不退步），且观测里可直接数出每角色
   样本存量距 `MIN_ROLE_CASES` 的差距。
