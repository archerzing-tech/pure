# 插话处理逻辑改版设计：并线/另线二分（2026-10-28）

> **用户定调原文**：插话输入首先需要一个暂停动作，就像正在发言突然被人打断问个问题。暂停后思考插入内容是并线处理还是另线处理——并线=插话内容与当前上下文相关，并入当前线；另线=与当前对话过程无关（例：正在生成 PPT，插入「现在几点了」），另开一条线。硬约束：**尽可能不增加 system prompt 负担，通过工程机制和手段处理**。
>
> 关系：本文是插话逻辑改版的施工权威；端口边界沿用 docs/framework-reform-2026-10.md 二期落地的 interjectionPort.ts 契约（对接点/插入点不动，只换边界内实现）。插话 v2 的引擎件（holdGate/taskState/真暂停链/SteerBus/定向投递）保留，卸的是九类判定与分发。
>
> **第三次定调（呈现层，2026-10-28）**：用户对之前实现的插话处理、显示、回复全不满意，**不得再出现之前的方式**——「插话处理中…」状态行、ack 行转收执气泡、「追加委派：XX 单独补跑」机制气泡、队列卡、机械确认句，全部退役。

## 〇、呈现层契约：对话流里引擎不发声

对话流只允许三种声音：
1. **用户原话**（回显气泡——插话确认的唯一形态：话已入流，静静躺在那，像正常发消息）；
2. **模型的自然话语**（主线模型消化插话后的自然承接 / 旁答的自然回答 / 收尾汇总里自然带出「你刚才说的 X」）；
3. **渲染产物**（委派卡/支状态卡/图表——任务卡的自然延伸，不新增任何插话专属 UI）。

禁令：无 ack 状态行、无「处理中」广播、无机制气泡、无铺排解说、无固定话术、无队列卡。机制状态（在飞/排队/停支）由既有工具卡与支状态卡表达。裁决器 receipt 只在必须即时确认处（stop/转新任务排队）出现，且必须像人说的一句话（裁决器提示词约束：短、点名具体事、零客套）；并线默认不出 receipt——主线模型下一轮的自然承接才是真正的回应。

工程配套：ack 临时行机制退役，`createAck` 语义改为「回显气泡引用」（旁答气泡锚定用）；`settleAck` 的气泡替换路径删，仅保留锚定与销账。

## 一、对用户模型的五点工程细化（裁定+理由）

**细化 1：暂停分「嘴/手」，话头=嘴，立即停（2026-10-28 四次定调，替换 holdGate 扣边界方案——用户真机否决：说完这句才停/静止随机时长不像被打断）。**
- **嘴（思考流在吐字）→ 立即掐流重入**：已吐的字渲染留底不消失；判定完带原话重新开口。复用真暂停链机制（掐流/渲染留底/原话重入，b7228ec 已部署验证）。总延迟=判定 1–2s+立即重入，比等边界更短更确定（无死线随机放行）。
- **手（工具执行/并行支）→ 不打断**：做完当前动作，下一 THINK 边界消化原话（并线路）。支级粒度：点名支消化，其余无感。
- **旁线不停嘴**：思考流继续，旁答并行，答案气泡插入。
- **任务暂停（重）**：仅 action:stop 触发真暂停链（宽限+abort 转发）。
- **holdGate 退役**：并线路流已断无边界可扣；工具路模型本未说话无需闸；两路径统一收口于「原话进下一轮思考输入」。竞态兜底：掐流扑空（话刚说完）→自然退化边界注入路径。
- **成本诚实账**：重入=丢弃半截思考重想，前缀缓存使其便宜；频繁插话的节奏抖动真机观察，若疼再议（半句 <N 字不掐直接说完的阈值）。

**细化 2：九类压缩为二分 + 一个机械动作。**
现有九类 relation（steer/fold/cancel/question/…）是宿主替模型做细分决策——正是「干扰大模型能力」。改版后：
- 判定只输出 **`inline`（并线）| `sideline`（另线）**，inline 可附带 `call_id`（用户点名某支）与 `action:stop`（模型/用户明确要停）。
- **并线的全部子形态（转向/追加/取消一部分/改向）宿主不再细分**——原话直投注入流，当前任务模型下一轮自己消化怎么转、怎么折、怎么停。宿主保留的唯一机械动作是 stop 掐流（这是引擎手脚：abortController，不是语义决策）。
- 误判有兜底：**另线路也把原话注入主流**（标注旁答事实）——若「无关」判错了（其实相关），主模型下一轮看到原话会主动承接，判定错误被注入机制对冲，不是单点故障。

**细化 3：即时确认靠回显，不靠暂停。** 感知延迟的解药是确认不是更狠的暂停——插话到达回显气泡立刻出现（用户自己的话入流），裁决收执秒回或不发。等待从「没反应」变成「它知道了，忙完这口就来」。长工具期（跑 2 分钟测试）inline 插话等边界注入，回显已给足确认。

**细化 4：另线分两档。**
- **旁答**：简报内可答（时间/寒暄/称呼），零工具即时答，答案回注。
- **新任务**（需要能力/多轮的无关请求，例「顺便查个天气」）：收执一句自然话告知「当前任务跑完就做」→ 进队 → 收尾后自动开新轮消化。真·并行另线（同 session 双回合）是工程深坑且多会话面板已可手动并行，一期不做。

**细化 5：置信偏置——低置信偏并线。** 误判不对称：无关话进主流=任务分心；相关话走另线=旁答+回注兜底。但「插话不丢」是最高不变量——裁决器低置信时一律按并线直投，sideline 只在高置信时走。宁可打扰，不丢话。

## 二、两路处理管线

```
用户插话到达（对接点 interject()，契约不变）
  │
  ├─ ① 回显气泡立即入流（即时确认，唯一呈现——无 ack 状态行）
  ├─ ② 话头暂停（嘴/手分开）：思考流在吐字→立即掐流（渲染留底），判定完
  │     带原话重入；工具/支在飞→不打断，下一边界消化；旁线不停嘴
  ├─ ③ 语义判定：裁决器 LLM（提示词内嵌裁决器，非常驻）
  │      输出：inline | sideline | new_task（+call_id? +action:stop? +receipt?）
  │      低置信 → 一律按 inline 直投（插话不丢优先）
  │
  ├─ 并线 inline ────────────────────────────────────────────
  │    ④ 原话直投：SteerBus 入队（点名支→定向，广播→父+各支）
  │    ⑤ action:stop → 宿主掐流（唯一保留的机械动作）
  │    ⑥ 下一 THINK 边界 P1 注入原话；模型自己消化（无宿主代判、
  │       无折入铺排气泡——派支走正常委派卡）
  │    ⑦ 闸开，主流继续；真正的回应=主线模型下一轮的自然承接
  │
  ├─ 另线 sideline ──────────────────────────────────────────
  │    ④ 判定落定即放闸（主流立刻继续，不等旁答）
  │    ⑤ 旁答管线并行：简报（原话+任务态一行+envFacts 含时间）→
  │       便宜快模型 → 普通助手气泡插入（无「旁答」标签，就是回答）
  │    ⑥ 原话+答案一行机制事实回注主流（收尾不漏项、不重复答）
  │    ⑦ 旁答失败退化：原话按并线注入，主模型自己答
  │
  └─ 新任务 new_task ────────────────────────────────────────
       ④ 放闸照旧；收执一句自然话（「这个跑完就弄」级别，现场措辞）
       ⑤ 进队，当前回合收尾后自动开新轮消化（queueInterjectTask 承载）
```

**收执纪律**（一期已定，沿用）：receipt=裁决器现场措辞，缺席沉默；另线的「收执」=旁答内容本身。

## 四、删除清单（边界内替换）

0. **holdGate 软暂停闸**：扣边界职责消失（嘴/手分开后无闸可扣），整件退役；死线/放行语义由掐流重入与边界注入两路径天然承载。

1. **九类 relation 契约与 schema**：INSERTION_CLASSIFY_PROMPT 的九类说明 → 二分+call_id+stop 三字段。
2. **九类处置表分发臂**：classifyAndApply 的大 switch → 两臂（注入臂/旁答臂）。
3. **P2 合成派发的 fold 部分**（takeSyntheticToolCalls 的 scope 追加折成委派调用）：宿主替模型决定派支，违背总方向——退役。追加原话进主流，模型自己决定怎么派支。**resume 部分（点名续跑停支的机械重派）保留**。
4. **随 fold 退役的框架件**：foldInInstruction/foldInScopeAddition 宿主入口/fold 铺排话术一批。
5. queueInterjectTask（收尾排队）保留为聚合窗兜底；SteerBus/FoldInLedger（水位）/DelegationControlPlane/holdGate/taskState/真暂停链全部保留（机械件）。

## 五、不变量（沿用蓝图 §六）

插话不丢（旁答失败也退化进主流）；账不平不收工（ledger 不动）；人格红线不动；机械解析豁免（时间/钟表归引擎）；缓存纪律（动态装配只走消息层注入件）。

## 七、真机验收点

1. **呈现（最优先）**：插话后对话流里只有——回显气泡、模型自然话、既有任务卡。零 ack 状态行/机制气泡/队列卡/机械确认句。
2. 跑动中（思考流吐字时）插「加上 XX 再总结」：**字停半空（留底），1–2s 后带着插话重新开口**，无铺排气泡；委派走正常卡片。
3. 工具执行中插话：在飞工具跑完，下一边界消化，工具卡无异常。
4. 跑动中插「停，方向不对」：真停，收执一句自然话（现场措辞，零客套）。
5. 跑动中插「顺便查下 XX」：收执告知跑完就做，收尾后自动开新轮。
6. 跑动中插相关但判成另线（构造）：主模型从回注事实里主动承接——误判不丢事。
7. 掐流扑空竞态（话刚说完）：原话走边界注入路径，无损。
8. 常驻 system prompt：改版后 INSERTION_PROTOCOL 指针 ≤100tk，总量不升。
