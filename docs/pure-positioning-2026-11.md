# pure 定位（2026-11）

> 状态：**定稿（2026-11-05），定位表述权威**。基线 `a968e68`。
> 本文管「pure 是什么、凭什么成立、什么算走偏」；施工口径归 [two-legs-plan-2026-11](two-legs-plan-2026-11.md)（W1–W5），决策归属判据归 [decision-boundary-2026-11](decision-boundary-2026-11.md)，多 agent × 自进化的结构归 [multi-agent-self-evolving-architecture](multi-agent-self-evolving-architecture.md)。三份不重复：那份管怎么建，这份管怎么说不走样。
> 源头：2026-11-03 用户定调；2026-11-05 复核后按「无说教，有机制」口径收敛表述。

## 一、一句话

> **pure 不教模型怎么做事，只保证模型能把事做成。**

## 二、正式表述

pure 是一个**多 agent、可自进化的通用智能体运行时**。

它的形态是一组开放的能力面——工具、插件、技能、通道、记忆——不预设流程，不规定章法，只守住两样东西：**输入输出的契约**，和**做事的底线**（权限、可逆、审计、诚实）。

一件事怎么做、拆不拆、用什么做、做几步、怎么呈现，全部由模型在运行时决定。

pure 只做模型做不了的两件事：把手脚伸到模型够不到的地方（本地系统、浏览器、渠道、跨会话记忆），把结果变成模型能判断的证据（可观察、可验证、可回退）。

两条腿走路：一条是**能力层持续变厚**——接入成本更低、原语更强、反馈更真；一条是**模型层持续跟进**——任何一代 SOTA 接入即用，并用评测回答「它适合什么」。两条腿互不绑架：模型换代不需要改 pure，pure 升级不需要换模型。

多 agent 与自进化不是两个功能，是同一件事的两面：模型能自己开分身，也能把这次的经验留下来，下次直接用。

## 三、三条原则

写在所有设计评审的最前面，用来挡需求：

1. **无说教，有机制。** 不规定模型怎么想；只保证事情可执行、可观测、可验证、可回退。
2. **能力无上限，入口有权威。** 工具可以无限长；同一件事只留一个权威入口、一份实现。
3. **提示词要薄，运行时不能薄。** 判断权归模型，物理约束归宿主。

三条原则与 [decision-boundary-2026-11](decision-boundary-2026-11.md) 的四分归属表是同一件事的两种说法：

| 归属 | 谁持有 | 定位语言里的位置 |
|---|---|---|
| **模型** | 何时做、做什么、按什么顺序、触发与否 | 「怎么做事是模型的事」 |
| **系统（手脚）** | 怎么做成、失败怎么递回、现状怎么照给模型 | 「pure 只提供手脚与证据」 |
| **物理不变量** | 预算上限、超时、原子写、终态保证 | 「运行时不能薄」 |
| **契约（用户意志固化）** | 人格、语言、交互语义、呈现标准 | 「底线与契约归宿主」 |

裁定规则不变：系统持有第一行任一决策 = 越位；持有后三行 = 正当。

## 四、三层结构

定位不是两条腿，是三层。机制层不是第三条产品线，是另外两层的地基。

| 层 | pure 提供什么 | 明确交给模型什么 | 判据 |
|---|---|---|---|
| **能力层（手脚）** | 工具、插件、技能、通道、浏览器、记忆、跨会话状态 | 用哪个、怎么组合、并行还是串行 | 加一个能力的成本；返回的信噪比 |
| **模型层（代际）** | 多 provider 接入、能力探测、按任务的评测与路由 | 选哪个模型、怎么用它的长板 | 新模型上线到可用的小时数；评测区分度 |
| **机制层（地基）** | 权限四模式、可逆性、审计、账目、上下文预算、缓存序、验证回路、失败事实注入 | 路线裁决、是否重试、是否换路、是否停支 | 宿主语义正则数量；删掉一条机制后事故率 |

三层各自的膨胀方向不同：能力层该**长**，模型层该**薄**（接入成本趋零），机制层该**稳**（不随模型换代改）。

## 五、与原表述的差异

原始定调的方向成立，但四处按字面执行会伤到产品，表述按下表收敛：

| 原表述 | 定稿口径 | 为什么 |
|---|---|---|
| 没有章法、没有规矩 | **无说教，有机制** | 字面执行会砍掉权限、缓存序、验证回路。这些不是「规矩」，是物理定律 |
| 一堆工具和插件的集合 | **开放的能力面，一个能力一个权威入口** | 「杂乱」是种类无上限，不是同一件事五个入口、三份实现 |
| 两条腿（手脚 × 模型） | **手脚 × 模型 × 机制** | 机制是第三条腿，只能长在机制层，不能占模型的决策位 |
| 结合 SOTA 模型 | **零成本跟进，且能证明谁适合什么** | 「支持很多 provider」不等于接上了这条腿；接入成本与评测区分度才是 |

第四条隐含一个转向：模型层的 KPI 不是「支持了多少家」，而是「新模型上线到可用要多久」和「评测能不能回答它适合哪类任务」。

## 六、为什么这个定位成立

### 6.1 站得住的三个理由

1. **符合 scaling 逻辑。** 把智能押在模型上、宿主不与模型竞争，是过去两年唯一没被证伪的策略。Anthropic 把 Claude Code 系统提示砍约 80% 无回归（2,686→514 词，2026-07）；长任务的胜负越来越多由上下文经济、验证回路、缓存命中决定，而不是提示词。
2. **模型中立是真实的代际红利。** 模型三个月一换，绑定单一厂商的 harness 会被每次代际切换惩罚。多 provider + 能力探测 + 评测路由的价值，在换代期才显现。
3. **押中了模型厂商不做的空白。** Cowork、Codex 都在往通用 agent 走，但它们不做中文渠道、不做插话、不做富呈现降级。交互智能（插话、证据循环、呈现、渠道）是主流没有对等物的部分——这才是护城河，不是工具数量。

### 6.2 必须正视的三个风险

**风险一：「无章法」会被误读成「没有 harness」，而 2026 的竞争恰恰是 harness 竞争。**

Claude Code 把整个 harness 围绕 prompt caching 建，缓存命中率掉下来要开 SEV（2026-02）；Anthropic 专门写长任务 harness 的设计方法（2026-03）与「brain 与 hands 解耦」（2026-04）；Terminal-Bench 头部从 8 月的 58% 涨到 10 月的 85%，差距主要来自 harness 而不是模型。同一个模型换个 harness 能差出数量级。

所以「无章法」只能指**提示词层与语义判断层**，不能指运行时。删的是说教与猜判，不是权限、账目、确定性自救、上下文预算。这条不写清，施工时一定被理解成「把机制也删了」。

**风险二：「工具和插件集合」正在商品化，不构成定位。**

MCP 与 Open Agent Skills 已是跨厂商标准；Codex 把 Skills 做成一等公民（2026-02）；OpenClaw 两个月冲到约 19.6 万星（2026-02）。**工具数量不是壁垒**，工具的质量才是：描述像不像接口、返回是否高信噪、错误是否可读、是否幂等可回退。定位句写「能力面」，不写「工具堆」——后者听起来像货架，前者才是基础设施。

**风险三：「结合 SOTA」有结构性时差，而且模型开始自带编排。**

模型厂商的 harness 与模型共同训练（Cowork、Codex），第三方 harness 天然吃「能力税」。更关键的是 Kimi K2.5 已在做 **self-directed agent swarm**：模型自己开最多 100 个子 agent、1,500 次工具调用，不需要预定义 subagent（2026-01）。

这意味着宿主硬编排多 agent 会从资产变成负资产。**对策不是删掉编排，是收缩职责**：宿主只管资源、隔离、权限、账目、回收；「要不要开、开几个、怎么分工」交还模型。机制留下，裁决权交出去。

### 6.3 自进化必须带验收

「可自进化」没有闭环就是营销词。生产可行的是记忆、技能库、工具自生成三层；权重级（SEAL 一类）不是 pure 的战场，不写进定位。

自进化的验收闭环只有四段：

> 经验被写下 → 下次被检索到 → 任务指标改善 → **可归因、可回滚**

缺归因或回滚的自进化是负债。这与 [multi-agent-self-evolving-architecture](multi-agent-self-evolving-architecture.md) 的三条防缠原则同向：进化产物只有声明式文件一种形态，观测单向，事件即接口。

## 七、边界：明确不做

| 不做 | 理由 |
|---|---|
| 自研模型 | 两条腿的前提是承认模型层由别人推进 |
| 云端托管平台 / 多租户 | 定位是个人与团队的本地运行时，不是平台生意 |
| 预设角色市场 / 固定工作流模板 | 角色与流程由模型运行时决定，预置即越位 |
| 与模型厂商的 harness 正面竞争通用编码 | 它们有模型协同设计优势；pure 占它们不做的位置 |
| 权重级自进化 | 不可审计、不可回滚，超出运行时职责 |
| 安全加固类全项（skills 签名、跨平台沙箱、MCP 投毒扫描） | 沿 2026-09-17 决策；执行正确性（注入防御）除外 |

差异化的准确表述是：

> **模型厂商做「最强的执行智能」，pure 做「模型愿意待着的那层壳」——中文渠道、桌面交互、呈现、可审计的多 agent 协作、模型中立。**

## 八、走偏信号

定位不靠宣言维持，靠这几个可观测信号：

| 维度 | 走偏信号 | 健康信号 |
|---|---|---|
| 提示词 | 常驻段重新增长；新增「必须先 X 再 Y」 | 常驻段稳定或下降；流程改成事实注入 |
| 机制 | 宿主语义正则、意图闸门变多 | 宿主语义正则只减不增；新机制过四分归属表 |
| 工具 | 同一能力多入口、多实现 | 一能力一入口；新增工具只改一处 |
| 模型 | 新模型上线要改代码 | 配置 + 探测即可用；评测给出任务适配 |
| 自进化 | 只记录、不归因、不回滚 | 四段闭环可跑；关掉总开关行为逐字节一致 |
| 差异化 | 只比工具数量与榜单分数 | 比交互、渠道、呈现、可审计性 |

前五行任一走偏，都说明定位正在退化成「普通 shell agent + 一堆工具」——那正是这个定位要避免的终点。
