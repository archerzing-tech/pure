# 对话智能升格蓝图：从「能干活」到「像人一样统筹」

> 2026-09-25 用户定调并授权（最高权限，可大刀阔斧）：pure 的会话体验要**超过 Claude**，具备人类大脑处理事情的灵活度——统筹兼顾、及时止损而不是事后对齐、综合判断不重复问不重复做不重复规划、按轻重缓急排优先级、能并则并当分则分、处事有分寸又合逻辑、瞄准用户的背后预期处理。**此前一切与本文冲突的约束、路线、叙事、处理与回答逻辑，以本文为准。**
>
> 硬约束只有一条不变：这是一个**多 agent 系统**（父 agent + 多个子 agent），每一项能力都必须同时回答「父怎么做、子怎么做、信号怎么跨越父子边界」。

---

## 0. 一句话总设计

**父 = 大脑（统筹/止损/优先级/预期），子 = 手（执行/回报），宿主 = 神经（信号的即时送达与持久存活）。**
过去一年的改进把「手」练强了（插话分类 438/450、折入代执行、relay 流水线、快照恢复）；本蓝图补的是「神经的即时性/可达性/持久性」和「大脑的统筹层」——差距不在能力有无，在三件事：**即时**（话到即达、停即真停）、**可达**（信号穿过父子边界）、**持久**（关机不丢）。

## 2. 现状底座：保留资产 vs 推翻清单

**保留（已验证的机械层资产，本蓝图的地基）**
- 五分类插话管线（question/steer/premise-change/goal-change/task/chatter）+ 正则快路径 + 回执 ack + 折入/代执行/取消协议（`DynamicInsertionCoordinator`、`Planner`、chat.ts 2410 起的全链）
- 父子共享 steer 队列的**通道接线**（`SubagentOrchestrator.ts:465` 已把 takeSteerMessages 透传给每个子代理引擎）——缺的只是 GUI 路由喂它
- 快照 V3 持久化 + 恢复（messages/计划游标/活动面板，`store.ts:48-94`、chat.ts:2142-2191）
- relay 接力流水线、并行 reads 池、worktree 自动隔离、收尾合并卡、完成通知、对话内进度播报
- cancel() 硬杀链（`chat.ts:5939-5944`，立即转发 abort 给在跑工具）——「真即时暂停」的现成零件
- CLI 已有 FSStore（`cliHarness.ts:352-355`）与稳定子代理 sessionId（`sub_{parent}_{role}_hash(args)`，同参重派即命中 checkpoint）——跨重启续跑的现成零件
- 防缠三原则（产物唯一形态 / 观测单向 / 事件即接口，2026-09-20 定调）继续作为工程纪律

**推翻（本蓝图明确废弃的旧范式）**
1. **「事后对齐」范式**：插话等边界、错误跑完再收账——对齐前移到话音落地时（第 1 期）与自查前置（第 5 期）
2. **question 旁答 fire-and-forget**（chat.ts:2540-2561「主循环根本不知道发生过」）——问答必须入账（第 1 期）
3. **排空式暂停的「假即时」**：文案说「马上停下」、实为等在飞委派跑满 30 分钟（第 1 期）
4. **「已排队，生成完成后自动发送…」旧文案**（i18n.ts:145）与 `queuedWhileStreaming` 死路径（main.ts:253）——被插话分类链取代多年，清掉
5. **冲突甩手动命令**（worktreeFinish conflict → abort + toast 让用户自己 git merge）——冲突是 agent 该接的活（第 6 期）
6. **「所有插话一个大池」的无寻址信号**——信号必须带 target（第 1 期起）

**旧约束取舍**
- 「提示词不引案例原句防八股」「按步提交」「无 AI 署名」照旧（质量纪律，与方向无冲突）
- 「控制行字面量不可动」保留：它是解析器契约（如 `## 计划 n` 标记），本蓝图不依赖改它；若某期确需动，单独评审
- 拟人化要求**升格不废除**：并入第 5 期「预期与分寸」体系
- 安全/权限加固继续不做（2026-09-17 定调）；止损机制是智能行为不是权限墙，兼容
- 旧路线图（北极星第 6 步收官项 T1/T2/T3/S1 等）与本蓝图争抢工期的，**一律让位本蓝图**，原项顺延

## 3. 七期落地

### 第 1 期「即时性」：话到即达、停即真停 ⭐ 先打

**目标**：判例 1–4 全绿。这是「事后对齐 → 实时对齐」的地基，全是「通道已存在、差最后一接线」的活。

**1a. 插话定向投递（信号寻址）**
- `pendingSteers` 大池升级为带 target 的投递：steer/question 生成投递项 `{text, target: 'parent' | 子代理 callId | 'all'}`。用户话里点名某支（「jev 那个…」）→ 宿主分类时已能从 CANCEL_PART_RE/GOAL_CHANGE_RE 同族匹配到具名对象；不点名但对准在飞工作的 → `all` 或父级
- GUI 路由改造（chat.ts:2464-2476）：委派在飞时 steer **不再**一律扣到 foldIn——带子代理 target 的直接进定向队列（子代理下个 THINK 边界取走，`AgentLoopEngine.ts:279` 拉取点已存在）；仅「新增工作」类仍走 foldIn 汇合轮
- orchestrator 侧：按 callId 寻址分发（每个在飞委派一个队列引用），`SubagentOrchestrator.ts:465` 透传点改为取「自己那份 + 全体份」
- 回执文案如实：「已直接转给正在跑的 XX 那一路」/「收齐后并入下一轮」两种，不再一律「已转达」

**1b. question 入账**
- `answerMidrunQuestion`（chat.ts:2540-2561）旁答保留，但问答对以一条系统消息折进运行回合上下文（模型下个边界可见，复用折入的投递闸门机制）；旁答失败不再静默，明说「这个问题我暂时没答上来，收尾时统一答」

**1c. 暂停真即时**
- pause 语义重排：LLM 流照旧秒停；在飞工具进入 **宽限期**（默认 8s，可配）：宽限内自然收尾最理想；到期未完 → 转发 abort（复用 cancel 链的 forwardAbort）。`ToolExecutionCoordinator.ts:299-307` 的「pause 不转发」改为「pause 宽限后转发」，reason 送达 toolStop——**顺带修掉 `isPauseAbort` 在 GUI 活链路不可达的接线断层**（ToolRegistry.ts:233 的 parentSignal 现在从不携带 pause reason）
- 委派工具在宽限到期被掐 → checkpoint 照存（`SubagentOrchestrator.ts:631-632` 已不分原因存），卡片如实标「宽限后中断，继续时从断点接」
- 对写文件等**不可安全中断**的工具：声明 `metadata.interruptible`，不可中断的仍排空但回执如实（「这一步写盘中，等它落完（约 Ns），已跳过后面排队的事」）
- Esc 语义统一：prompt 聚焦 Esc = pause、document Esc = cancel 的双轨收敛为一个确认层级（先 pause，再按一次=cancel，回执说清差别）

**验收**：真机判例 1–4 + 单测（定向投递寻址、宽限期状态机、isPauseAbort 可达性——用真实协调器而非绕行信号）；沿用 T01–T30 回放器加 4 条即时性判例。
**量级**：中。第 1 期完成后即可发版实测。

### 第 2 期「持久性」：关机不丢，随时接着聊

- **子代理 checkpoint 换 FSStore**：GUI 的 stateStore 从 MemoryStateStore（chat.ts:1504，重启即丢）换成 CLI 同款 FSStore（已实现，`cliHarness.ts:352`）——稳定 sessionId 机制不动，同参重派即命中。落盘位置 `~/.pure/checkpoints/`，随会话删除清理
- **暂停态显式持久化**：快照加 session 级 `paused: true`（store.ts V3 → V4 小升版，兼容读）；重启恢复时重建「继续」条（现在只在活的 Interrupted 分支创建，chat.ts:5987-6005），点击等价「继续」
- 续跑回执如实：「从上次断点接」（checkpoint 命中）/「那部分没存上，重跑这一段」（未命中）
- **验收**：判例 5 的真机全流程（跑一半→暂停→退出 app→重开→继续→子代理从 checkpoint 续）。
**量级**：中小。

### 第 3 期「账本」：不重复问、不重复做、不重复规划

**会话账本（SessionLedger）**，宿主持有、进快照持久化：
- `asked`：澄清问题指纹 → 用户的回答（提问前先翻：同一件事不问第二遍，直接用已有答案并说明「按你刚才说的」）
- `done`：动作指纹（意图+参数规范化 hash）→ 结果摘要（动手前先翻：已做过就复用并告知，不重跑）
- `plans`：计划指纹与状态链（配合既有 planSeq/planReplaced 语义：细化不重开，重开需明说「之前的计划作废，原因是…」）
- 注入方式：父 agent 每轮上下文尾部的压缩清单（复用 token 预算压缩体系 8.x，不裸灌）；指纹命中在提示词协议层教（INSERTION_PROTOCOL 同级新增 LEDGER_PROTOCOL），宿主在分类/折入时做结构化兜底
- 父子分工：账本归父；子代理产出回流时由父记账——子的回报格式（最终产出含「做了什么/结论」）已在编排器结果封装里，够用

**验收**：判例 6 真机 + 单测（指纹去重、账本随快照持久化）。
**量级**：中。

### 第 4 期「调度」：轻重缓急、能并则并、当分则分

- **插话即优先级**：五分类 kind 直接映射处理级——stop/premise-change/goal-change = 中断级（现在处理）、steer = 边界级（下个边界）、question = 即答级（旁答即刻）、task = 队列级、chatter = 陪伴级。现有代码大体已是这个顺序，本项把它**显式化为调度策略**并写进回执（「这句急，先办」「这句排上了，办完手头就轮到」）
- **任务队列升级**：taskQueue 加 priority 字段（现在纯 FIFO 分 lane，taskQueue.ts:103），插话产生的 task 按分类定级插队；用户口头说「这个急」→ 提级并回执确认
- **批/分协议**（提示词层，COMPLEX_TASK_PROTOCOL 增补一条「批量决策」）：同类小活合并一批一次汇报；有依赖的拆 relay 链；不可合并的明确说为什么分开——「能一块干的绝不分两步，需要多步的绝不硬凑」两条都进协议，带内容锁测试
- **验收**：判例 7–9 真机 + taskQueue 优先级单测。
**量级**：中。

### 第 5 期「预期、止损与分寸」：瞄准背后预期，止损前置

- **预期画像（会话级、启发式、轻量）**：信号取用户消息节奏（长短/频率/负面词/纠错次数）→ 直给/常规/详述三档 → 调播报粒度与回执长度（判例 11）。不做重型用户建模，规则可解释、可关
- **止损检查点（运行时化）**：把「事后对账」前移为三个前置检查点——① 不可逆动作前确认（T22 已修，保持）；② **连续 2 次同类失败** → 自动收缩重试面并主动告知（复杂任务协议「失败全账」的运行时化）；③ **前提失效即停**：工具结果与既有假设冲突时立即停下对表，而不是按旧假设跑完（premise-change 协议从「用户宣告」扩展到「agent 自查」，判例 10）
- **分寸条款**：多说一句/少说一句的判断规则并入拟人化协议体系（何时补背景、何时直给、何时只回执不展开）；对话内播报纪律（2026-09-25 拆条那套）作为粒度范本
- **验收**：判例 10–11 用真机回放脚本（复用 T01–T30 回放器思路，前提冲突注入式判例）。
**量级**：中大（协议 + 观测 + 回放样本都要建）。

### 第 6 期「并行与合并」：随手开分支，随时合回来

- **合并卡升级**（worktreeFinishCard）：逐文件 diff 审查 + 文件勾选选择性合并（git checkout <branch> -- <paths> 语义）；**冲突不甩手动命令**——冲突文件直接开成父 agent 的一个协助回合（「A 和 B 都改了 X，我建议这样合，你看下」），agent 提方案用户拍板（判例 12）
- **主动开分支**：会话创建/任务下发时可选「为此任务开独立分支」，不再只靠选夹撞车被动触发
- **反向同步**：主区前进后，worktree 会话给一键「同步主区进展」（手动触发 merge from main，不自动）
- worktree 管理面板 + prune（生命周期收口）
- **量级**：中。

### 第 7 期「架构纵深」：按第 1–6 期落地后的体感决定

- 分支级中断（只停一支委派）：委派粒度的信号注册表，与「可中断工具批」是同一块架构工作
- 指令级计划断点续传（工具调用重放去重已有雏形可作基础）
- CLI 接 steering 通道（Harness.ts:129「Omitted = no steering channel」，CLI 提话目前完全进不了运行回合）——CLI 同权

## 4. 跨期工程纪律

1. **每期独立可发布、可实测**：一期一个版本号 + 真机判例回放过线才收（沿用 T01–T30/复杂任务案例集的验收文化）
2. **协议新增必带内容锁测试** + 判例不引原句（防八股，既有纪律）
3. **防缠三原则**不破：产物唯一形态、观测单向、事件即接口——寻址投递、账本、优先级都走既有事件/快照通道，不开旁路
4. **父子同权检查**：每期收尾时过一遍清单——这项能力父有子有没有？信号过边界丢不丢？重启后还在不在？
5. token 成本：账本/寻址注入全部走预算压缩体系；插话分类 8s 超时 tradeoff 沿用，第 1 期顺带观测分类耗时分布，数据够再议便宜模型路由

## 5. 风险清单

| 风险 | 对策 |
|---|---|
| 定向投递被错误的子代理抢走（池→寻址迁移竞态） | 投递项带 target 原子入队；取队列时按 callId 过滤；单测锁竞态窗口 |
| 强杀把写文件等工具杀成半截 | `metadata.interruptible` 声明制；不可中断工具只排空 + 回执如实；被掐工具的结果一律不入账（沿用取消协议「部分产出不算结论」） |
| FSStore 并发写/路径冲突 | 键即稳定 sessionId（已唯一）；落盘原子写（tmp+rename） |
| 账本指纹误命中（形似实异） | 指纹 = 归一化意图 + 参数 hash 双重；命中只做「提示 + 一键确认」，不静默跳过 |
| 提示词新增过多互相踩（L1 片段膨胀） | 新协议逐条评审合并进既有协议块；每加一条跑全量回放防回归 |
| 止损检查点误报频繁打断 | 阈值从宽起步（2 次同类失败才触发）；误报率进右面板观测，数据说话再收紧 |

## 6. 落地顺序与节奏

第 1 期（即时性）→ 第 2 期（持久性）为第一波：合起来正是用户点名的「随时插话、随时暂停、随时继续」三件事的完整兑现，且大量复用现成零件。第 3–5 期（账本/调度/预期止损）是「人类大脑」的主体，第二波逐期推。第 6 期合并随需插队。第 7 期永远按体感数据决定做不做。
