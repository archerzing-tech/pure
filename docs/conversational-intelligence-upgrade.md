# 对话智能升格蓝图：从「能干活」到「像人一样统筹」

> 2026-09-25 用户定调并授权（最高权限，可大刀阔斧）：pure 的会话体验要**超过 Claude**，具备人类大脑处理事情的灵活度——统筹兼顾、及时止损而不是事后对齐、综合判断不重复问不重复做不重复规划、按轻重缓急排优先级、能并则并当分则分、处事有分寸又合逻辑、瞄准用户的背后预期处理。**此前一切与本文冲突的约束、路线、叙事、处理与回答逻辑，以本文为准。**
>
> 硬约束只有一条不变：这是一个**多 agent 系统**（父 agent + 多个子 agent），每一项能力都必须同时回答「父怎么做、子怎么做、信号怎么跨越父子边界」。
>
> **v2（2026-09-25 同日）**：用户补充关切「多 agent 在跑时遇到事情停不下来」。核实属实且比预想更彻底——在飞委派暂停后跑满自然寿命（内置角色 30 分钟）。裁决：**分支级中断从原第 7 期提级为独立第 2 期**；第 1 期的委派注册表（插话寻址地基）即为单支中断的地基。结构事实：子代理在父眼里就是工具调用，「停/续」的底座（cancel 硬杀链、引擎 Interrupted+checkpoint 不分原因存档、稳定 sessionId 命中续跑）全是现成的，缺的只是**按分支寻址的信号通路**。

---

## 0. 一句话总设计

**父 = 大脑（统筹/止损/优先级/预期），子 = 手（执行/回报），宿主 = 神经（信号的即时送达与持久存活）。**
过去一年的改进把「手」练强了（插话分类 438/450、折入代执行、relay 流水线、快照恢复）；本蓝图补的是「神经的即时性/可达性/持久性」和「大脑的统筹层」——差距不在能力有无，在三件事：**即时**（话到即达、停即真停）、**可达**（信号穿过父子边界）、**持久**（关机不丢）。

## 2. 现状底座：保留资产 vs 推翻清单

**保留（已验证的机械层资产，本蓝图的地基）**
- 五分类插话管线（question/steer/premise-change/goal-change/task/chatter）+ 正则快路径 + 回执 ack + 折入/代执行/取消协议（`DynamicInsertionCoordinator`、`Planner`、chat.ts 2410 起的全链）
- 父子共享 steer 队列的**通道接线**（`SubagentOrchestrator.ts:465` 已把 takeSteerMessages 透传给每个子代理引擎）——缺的只是 GUI 路由喂它
- 快照 V3 持久化 + 恢复（messages/计划游标/活动面板，`store.ts:48-94`、chat.ts:2142-2191）
- relay 接力流水线、并行 reads 池、worktree 自动隔离、收尾合并卡、完成通知、对话内进度播报
- cancel() 硬杀链（`chat.ts:5939-5944`，立即转发 abort 给在跑工具）——「真即时暂停」的现成零件
- CLI 已有 FSStore（`cliHarness.ts:352-355`）与稳定子代理 sessionId（`sub_{parent}_{role}_hash(args)`，同参重派即命中 checkpoint）——跨重启续跑的现成零件
- 子代理引擎的 Interrupted + checkpoint 存档**不分原因**（`SubagentOrchestrator.ts:631-632`）——被强杀/被单支中止时断点自动落袋，「停了能续」不需要新机制
- 防缠三原则（产物唯一形态 / 观测单向 / 事件即接口，2026-09-20 定调）继续作为工程纪律

**推翻（本蓝图明确废弃的旧范式）**
1. **「事后对齐」范式**：插话等边界、错误跑完再收账——对齐前移到话音落地时（第 1 期）与自查前置（第 6 期）
2. **question 旁答 fire-and-forget**（chat.ts:2540-2561「主循环根本不知道发生过」）——问答必须入账（第 1 期）
3. **排空式暂停的「假即时」**：文案说「马上停下」、实为等在飞委派跑满 30 分钟（第 1 期）
4. **「已排队，生成完成后自动发送…」旧文案**（i18n.ts:145）与 `queuedWhileStreaming` 死路径（main.ts:253）——被插话分类链取代多年，清掉
5. **冲突甩手动命令**（worktreeFinish conflict → abort + toast 让用户自己 git merge）——冲突是 agent 该接的活（第 7 期）
6. **「所有插话一个大池」的无寻址信号**——信号必须带 target（第 1 期起）
7. **「中途单飞子代理真中断不做为残差」**（3f7a1ba 记录在案的取舍）——v2 推翻：提级为第 2 期，「取消一支」从产出不算数（算力照烧）升级为真停 + 断点可续

**旧约束取舍**
- 「提示词不引案例原句防八股」「按步提交」「无 AI 署名」照旧（质量纪律，与方向无冲突）
- 「控制行字面量不可动」保留：它是解析器契约（如 `## 计划 n` 标记），本蓝图不依赖改它；若某期确需动，单独评审
- 拟人化要求**升格不废除**：并入第 6 期「预期与分寸」体系
- 安全/权限加固继续不做（2026-09-17 定调）；止损机制是智能行为不是权限墙，兼容
- 旧路线图（北极星第 6 步收官项 T1/T2/T3/S1 等）与本蓝图争抢工期的，**一律让位本蓝图**，原项顺延

## 3. 八期落地

### 第 1 期「即时性」：话到即达、停即真停 ⭐ 先打

**目标**：判例 1–4 全绿。这是「事后对齐 → 实时对齐」的地基，全是「通道已存在、差最后一接线」的活。

**1a. 插话定向投递（信号寻址）✅ 已落地（2026-09-25，commit 0f98a72）**
- 实现形态与原案两处有意偏差：①注册表用宿主 `agentActivities` 的**只读视图**（不另立账本，防缠三原则），编排器 AbortController 注册表按计划留给第 2 期；②点名匹配用**区分性 token 纯函数**（`src/shared/steerTargeting.ts`：候选词只被一支的 name+role+snippet 含有才算命中，打平宁可广播），不靠正则猜具名对象
- `pendingSteers` 条目带 `{message, target, displayText}`：target = `'parent' | 'all' | {branchCallId, branchName}`；投递/消费语义单一口径在 steerTargeting（广播人人可读、只有父边界收走；点名只投被点名支、也只有它取走）
- 编排器给每个分支的 takeSteerMessages 闭包包上分支身份（`{branchCallId, branchName}`），引擎拉取点零改动；折入闸门从「在飞恒 true」改为「父边界 && 无在飞」——身份检查结构性排除子代理偷折入
- 在飞 steer 不再一律折入：非取消型定向/广播直达干活中的分支（`SteerInjected` 事件 → 卡片 📨 回执既有）；取消型（cancelsPart）仍折入汇合轮，真停留第 2 期
- 回执按目的地区分：「已直接转给「X」那一路」/「在跑的几路都收到了」/父级照旧「已转达」
- **渲染一致性同刀落地**：重放剥壳（三框架前缀 → 用户原话；【系统接管执行】机制行整条不上屏）；回合收尾残留插话以用户原话重入（不再是引擎框架文开场）

**1b. question 入账 ✅ 已落地（2026-09-25，commit 70e0b31）**
- 实现形态：问答对走的是 pendingSteers 通道（不是另一条系统消息路）：`recordSideAnswer` 入账一条 `internal: true` 消息（引擎转录随存档走，重放由投影剥掉不冒充用户气泡），答上的 displayText=''（回合收尾账清即弃）、没答上的 displayText=问题原话（「收尾时一并答」承诺兑现为机制）；target 随在飞状态 parent/'all'
- 旁答失败不再静默：明说「这个问题我暂时没答上来——先记下了，收尾时一并答你」

**1c. 暂停真即时 ✅ 已落地（2026-09-25，commit 6793969）**
- pause 语义重排：LLM 流照旧秒停；在飞工具进入 **宽限期**（`PAUSE_TOOL_GRACE_MS` 默认 8s，`ctx.pauseToolGraceMs` 可配）：宽限内自然收尾最理想；到期未完 → `toolStop.abort(PAUSE_ABORT_REASON)`——**`isPauseAbort` 在 GUI 活链路从此可达**（reason 顺 toolStop → ToolRegistry → parentSignal 送达编排器 ：650 的暂停存档分支），委派被掐 checkpoint 照存、卡片如实标暂停
- `metadata.interruptible: false` 豁免：写盘类照旧排空到自然结束；**升级硬停（第二通道）比豁免大**——Esc 第二下/会话切换时立即掐
- **升级硬停走独立信号通道**：主 controller 一经 abort，二次 abort 是规范级 no-op（reason 换不掉），故宿主每回合并建 `hardStopSignal`，随 CodingAgent → Harness → ctx 贯穿；协调器一听到就 clearTimeout + 立即按 PAUSE_ABORT_REASON 掐在飞工具，**记账仍归暂停**（断点照存、卡片 ⏸）
- Esc 语义统一：Esc 双轨收敛为一个确认层级——第一下 = pause（「正在暂停」条），收尾期里再按 = 升级硬停；Stop 按钮照旧纯 pause
- 排队工具暂停后不再启动（'paused — not started'），配对结果照给（转录不挂空 toolCall）

**1d. 委派注册表（地基，第 2 期单支中断复用）✅ 只读半已落地（随 1a，commit 0f98a72）**
- 寻址数据源 = 宿主 `agentActivities`（callId/agentName/agentRole/inputSnippet 已在事件流里，观测单向）——不再另立 DelegationRegistry 花名册；第 2 期在编排器侧补 AbortController 注册表（只有「能 abort 的把手」是新产物）
- 稳定 sessionId/startedAt 已在编排器内部存在，第 2 期按需暴露

**验收**：真机判例 1–4 + 单测（定向投递寻址、宽限期状态机、isPauseAbort 可达性——用真实协调器而非绕行信号）；沿用 T01–T30 回放器加 4 条即时性判例。**单测与回放 4 判例已全绿（2026-09-25）**：判例1=conversationSamples 定向投递回放（点名直达+没点名广播）+ steerTargeting 矩阵 + 编排器收件人捕获；判例2/3=ToolExecutionCoordinator 宽限状态机四测（宽限内完成/到期掐断带 pause reason=可达性证明/interruptible:false 排空/升级通道即时掐+压过豁免）+ Esc 两档回放；判例4=1b 旁答入账/失败重入回放。**待真机 1–4 实测后收官。**
**量级**：中。第 1 期完成后即可发版实测。

### 第 2 期「分支中断」：停得下单支，续得回断点 ⭐ 用户点名的止损核心

**目标**：判例 13–14 全绿。把「取消一支」从产出不算数（算力照烧到跑完）升级为真停 + 断点可续，收口 3f7a1ba 残差。

**骨架规格（2026-09-25 用户设想 + 评审定稿）：子代理全生命周期状态机。** 用户原案「每个子 agent 具备启动/运行中/暂停/暂停中/resume/完成」评审后定型：四个主状态其实是四个**动作**（启动/暂停/继续/收尾），中间态才是**状态**；补第五个动作「中止」（止损是本期灵魂，「停掉这支」和「暂停这支」必须落不同终态）。

- **状态集**（`src/coding-agent/branchLifecycle.ts`）：委派中 delegating / 运行中 running / 暂停收尾 pausing（宽限期内，永不驻留）/ 暂停中 paused（断点已存）/ 终态三兄弟：已完成 completed（产出入账）、已中止 aborted（用户叫停：产出不入账、断点照存、可另起续）、已失败 failed（挂 cause：error/timeout/stalled，父按原因选下一步）。中间态各有逃逸口（收尾 8s 宽限 1c 现成；委派中 spawn 超时），**永不驻留中间态**
- **转移纪律**：结算类动作（spawned/pauseSettled/complete/fail）是运行结果的地面真相，从任何非终态可接受（漏看信号也对齐结果，不跟丢）；控制类动作（pause/abort）才查合法性——pause 幂等、终态拒绝、abort 压过一切
- **异常/重试两层**：子代理内部自愈重试（failurePolicy 升级线以内）**不迁移状态**——发 `branch_retrying(attempt, cause)` 事件，卡片亮灯不惊动父；重试耗尽落已失败，失败后的重跑是**父的决策**（新一次启动 + 血缘号），不是状态机内的边。resume 找不到断点不许悄悄从头跑——明说「没找到存档，重新跑了」
- **账本归属**：状态机住在编排器（它有生杀权），每支委派一条账（abort 把手 + 账本，`branches` 注册表）；宿主 agentActivities / GUI 卡片 / 父 OBSERVE 全是**投影**（观测单向，防缠三原则）；describe() 映射回既有活动词汇，卡片第一阶段零改动吃到真状态
- **落地进度**：✅ 状态机本体 + 注册表 + abortBranch(callId) 定向叫停 + 分支结算分支（branchController aborted 当且仅当点名叫停，老 webview 读不到 reason 也成立）+ persist-before-settle 顺序（存档先落、再结算）——委派中首事件→运行中、四类结算点全走 describe() 单一写手

- **定向 abort 通路（宿主半边）**：宿主分类出「停掉某支」（CANCEL_PART_RE/LLM cancelsPart 已有，补祈使式「停掉 X 那支」快路径）→ 按名字/callId 查 `branchView()`/agentActivities → 调 `abortBranch` → 子代理引擎 THINK 流秒停（既有 abort 链）；回执说清哪支被停、其余照跑
- **原子顺序锁死**：✅（编排器半边已锁：persist → settle）；宿主半边：被中止支的部分产出不入账从「提示词教学」升格为「机制强制」；排队未起飞的同名支一并清除
- **分支级继续**：用户「把 jev 那支接着跑完」→ 同参重派 → 稳定 sessionId 命中断点 → engine.continue；三种「继续」（整树/单支/计划续跑）统一入口命名与回执口径——用户永远知道点的是哪个继续；血缘号（第 2 次/续跑徽标）随事件走
- **relay 失效定义**：被中止支是 relay 上游时，下游 `relay.from` 消费者立即以明确错误落定（不挂死）；分派前拓扑检查提前报
- **卡片真实状态**：子代理卡片 paused/cancelled-by-user 真状态（状态机 describe 已供数），回放从事件流重建，historical 兜底保留
- **账目与观测**：branch_aborted / branch_resumed / branch_retrying 成一等事件（活动面板 + turnTimings）
- **不误伤**：单支中止是回合内分支级事件，回合与 autoContinue 照跑，父在 OBSERVE 知道这支提前结束并自己调整汇总口径

**验收**：真机判例 13–14 + 单测（定向 abort 只杀目标支、persist-先于-settle 顺序、relay 下游 fail-fast、排队支清除）；回放器加 2 条分支止损判例。
**量级**：中大（本蓝图最大单体工程，但「停/续」底座全是现成的，新写的只有信号通路与语义收口）。

### 第 3 期「持久性」：关机不丢，随时接着聊

- **子代理 checkpoint 换 FSStore**：GUI 的 stateStore 从 MemoryStateStore（chat.ts:1504，重启即丢）换成 CLI 同款 FSStore（已实现，`cliHarness.ts:352`）——稳定 sessionId 机制不动，同参重派即命中。落盘位置 `~/.pure/checkpoints/`，随会话删除清理
- **暂停态显式持久化**：快照加 session 级 `paused: true`（store.ts V3 → V4 小升版，兼容读）；重启恢复时重建「继续」条（现在只在活的 Interrupted 分支创建，chat.ts:5987-6005），点击等价「继续」
- 续跑回执如实：「从上次断点接」（checkpoint 命中）/「那部分没存上，重跑这一段」（未命中）
- 分支断点一并落盘：第 2 期的单支中止 checkpoint 同走 FSStore，重启后单支续跑不丢
- **验收**：判例 5 的真机全流程（跑一半→暂停→退出 app→重开→继续→子代理从 checkpoint 续；含单支中止后的重启续跑）。
**量级**：中小。

### 第 4 期「账本」：不重复问、不重复做、不重复规划

**会话账本（SessionLedger）**，宿主持有、进快照持久化：
- `asked`：澄清问题指纹 → 用户的回答（提问前先翻：同一件事不问第二遍，直接用已有答案并说明「按你刚才说的」）
- `done`：动作指纹（意图+参数规范化 hash）→ 结果摘要（动手前先翻：已做过就复用并告知，不重跑）
- `plans`：计划指纹与状态链（配合既有 planSeq/planReplaced 语义：细化不重开，重开需明说「之前的计划作废，原因是…」）
- 注入方式：父 agent 每轮上下文尾部的压缩清单（复用 token 预算压缩体系 8.x，不裸灌）；指纹命中在提示词协议层教（INSERTION_PROTOCOL 同级新增 LEDGER_PROTOCOL），宿主在分类/折入时做结构化兜底
- 父子分工：账本归父；子代理产出回流时由父记账——子的回报格式（最终产出含「做了什么/结论」）已在编排器结果封装里，够用

**验收**：判例 6 真机 + 单测（指纹去重、账本随快照持久化）。
**量级**：中。

### 第 5 期「调度」：轻重缓急、能并则并、当分则分

- **插话即优先级**：五分类 kind 直接映射处理级——stop/premise-change/goal-change = 中断级（现在处理）、steer = 边界级（下个边界）、question = 即答级（旁答即刻）、task = 队列级、chatter = 陪伴级。现有代码大体已是这个顺序，本项把它**显式化为调度策略**并写进回执（「这句急，先办」「这句排上了，办完手头就轮到」）
- **任务队列升级**：taskQueue 加 priority 字段（现在纯 FIFO 分 lane，taskQueue.ts:103），插话产生的 task 按分类定级插队；用户口头说「这个急」→ 提级并回执确认
- **批/分协议**（提示词层，COMPLEX_TASK_PROTOCOL 增补一条「批量决策」）：同类小活合并一批一次汇报；有依赖的拆 relay 链；不可合并的明确说为什么分开——「能一块干的绝不分两步，需要多步的绝不硬凑」两条都进协议，带内容锁测试
- **验收**：判例 7–9 真机 + taskQueue 优先级单测。
**量级**：中。

### 第 6 期「预期、止损与分寸」：瞄准背后预期，止损前置

- **预期画像（会话级、启发式、轻量）**：信号取用户消息节奏（长短/频率/负面词/纠错次数）→ 直给/常规/详述三档 → 调播报粒度与回执长度（判例 11）。不做重型用户建模，规则可解释、可关
- **止损检查点（运行时化）**：把「事后对账」前移为三个前置检查点——① 不可逆动作前确认（T22 已修，保持）；② **连续 2 次同类失败** → 自动收缩重试面并主动告知（复杂任务协议「失败全账」的运行时化）；③ **前提失效即停**：工具结果与既有假设冲突时立即停下对表，而不是按旧假设跑完（premise-change 协议从「用户宣告」扩展到「agent 自查」，判例 10）
- **分寸条款**：多说一句/少说一句的判断规则并入拟人化协议体系（何时补背景、何时直给、何时只回执不展开）；对话内播报纪律（2026-09-25 拆条那套）作为粒度范本
- **验收**：判例 10–11 用真机回放脚本（复用 T01–T30 回放器思路，前提冲突注入式判例）。
**量级**：中大（协议 + 观测 + 回放样本都要建）。

### 第 7 期「并行与合并」：随手开分支，随时合回来

- **合并卡升级**（worktreeFinishCard）：逐文件 diff 审查 + 文件勾选选择性合并（git checkout <branch> -- <paths> 语义）；**冲突不甩手动命令**——冲突文件直接开成父 agent 的一个协助回合（「A 和 B 都改了 X，我建议这样合，你看下」），agent 提方案用户拍板（判例 12）
- **主动开分支**：会话创建/任务下发时可选「为此任务开独立分支」，不再只靠选夹撞车被动触发
- **反向同步**：主区前进后，worktree 会话给一键「同步主区进展」（手动触发 merge from main，不自动）
- worktree 管理面板 + prune（生命周期收口）
- **量级**：中。

### 第 8 期「架构纵深」：按第 1–7 期落地后的体感决定

- 指令级计划断点续传（工具调用重放去重已有雏形可作基础）
- CLI 接 steering 通道（Harness.ts:129「Omitted = no steering channel」，CLI 提话目前完全进不了运行回合）——CLI 同权
- 孙代委派（子代理再派子代理）的注册表递归——若体感真需要再评估，当前编排为一层

## 4. 跨期工程纪律

1. **每期独立可发布、可实测**：一期一个版本号 + 真机判例回放过线才收（沿用 T01–T30/复杂任务案例集的验收文化）
2. **协议新增必带内容锁测试** + 判例不引原句（防八股，既有纪律）
3. **防缠三原则**不破：产物唯一形态、观测单向、事件即接口——寻址投递、账本、优先级都走既有事件/快照通道，不开旁路
4. **父子同权检查**：每期收尾时过一遍清单——这项能力父有子有没有？信号过边界丢不丢？重启后还在不在？
5. token 成本：账本/寻址注入全部走预算压缩体系；插话分类 8s 超时 tradeoff 沿用，第 1 期顺带观测分类耗时分布，数据够再议便宜模型路由
6. **UI 渲染一致性**（2026-09-25 用户定调）：会话过程不只是消息流——消息的显示、呈现、暂停、继续都必须「实时渲染 = 重载渲染」。规则：用户插话的持久形态只有引擎转录一份，UI 显示从内容派生（剥壳 choke point 单一：`transcriptProjection.visibleUserContent`），宿主机制行（系统接管口径等）永不冒充用户气泡；每期验收含「实时 vs 重载」对照判例（插话、卡片状态、继续条、回执的存活都要过一遍）

## 5. 风险清单

| 风险 | 对策 |
|---|---|
| 定向投递被错误的子代理抢走（池→寻址迁移竞态） | 投递项带 target 原子入队；取队列时按 callId 过滤；单测锁竞态窗口 |
| 强杀把写文件等工具杀成半截 | `metadata.interruptible` 声明制；不可中断工具只排空 + 回执如实；被掐工具的结果一律不入账（沿用取消协议「部分产出不算结论」） |
| FSStore 并发写/路径冲突 | 键即稳定 sessionId（已唯一）；落盘原子写（tmp+rename） |
| 账本指纹误命中（形似实异） | 指纹 = 归一化意图 + 参数 hash 双重；命中只做「提示 + 一键确认」，不静默跳过 |
| 提示词新增过多互相踩（L1 片段膨胀） | 新协议逐条评审合并进既有协议块；每加一条跑全量回放防回归 |
| 止损检查点误报频繁打断 | 阈值从宽起步（2 次同类失败才触发）；误报率进右面板观测，数据说话再收紧 |
| 被中止支是 relay 上游，下游挂死等产出 | 下游消费者立即 fail-fast 明确落定；分派前拓扑检查提前报（第 2 期机制） |
| 中断与存档竞态（断点存成半截） | 顺序锁死：先 persist checkpoint 再 settle 父级工具结果；单测锁序 |
| 三种「继续」（整树/单支/计划）用户分不清 | 统一入口命名 + 回执口径模板：「从哪、续什么、还剩多少」三要素齐才许出继续条 |
| 单支中止误伤回合 autoContinue | 分支中止定义为回合内分支级事件，回合照跑；测试锁 autoContinue 不被分支事件取消 |

## 6. 落地顺序与节奏

第一波 = 第 1 期（即时性）→ 第 2 期（分支中断）→ 第 3 期（持久性）：正好完整兑现用户点名的「随时插话、随时暂停（含停单支）、随时继续（含重启）」，且第 1 期的注册表就是第 2 期的地基、第 2 期的断点第 3 期落盘——同一块地基三层用，编排层只动一遍。第二波 = 第 4–6 期（账本/调度/预期止损分寸），「人类大脑」主体逐期推。第 7 期合并随需插队。第 8 期永远按体感数据决定做不做。
