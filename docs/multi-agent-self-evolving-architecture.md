# pure 北极星架构：多 Agent × 自进化智能体

状态：**总设计定稿（2026-09-20 用户定调），未实施**。定调原话：pure 是一个
"多 agent + 自进化智能体"。本设计回答两个问题：这两根柱子怎么长在同一副骨架上；
怎么保证后续迭代不越改越麻烦。

## 核心洞察：两根柱子是同一个循环的两个维度

- **多 agent 是空间维**：此时此刻，一支专家团队在并行干活；
- **自进化是时间维**：这团队上个礼拜比今天更笨，下个礼拜比今天更聪明。

把它们接起来的是同一个循环：

```
┌──────────────────────────────────────────────────────────────┐
│  运行时（团队）                                              │
│  任务 → 计划/委派（并行编排）→ 子 agent 各自执行 → 结果汇聚  │
│        ↕ 事件流（EngineEvent / SubagentActivity / 插话路由） │
├──────────────────────────────────────────────────────────────┤
│  观测层：一切运行留痕（E4.1 派发结局 / 工具观测 / 成本）      │
├──────────────────────────────────────────────────────────────┤
│  进化层：观测 → 归因/反思 → 生成改进物                        │
│          （记忆 / 技能 / 角色 overlay / 新角色 / 新工具 / 建议）│
├──────────────────────────────────────────────────────────────┤
│  产物层：改进物统一落盘 ~/.pure/ 各目录（声明式文件）         │
│          启动扫描 → 走既有 register 接缝 → 注册回运行时       │
└──────────────────────────────────────────────────────────────┘
```

多 agent 顺带解决自进化最缺的东西：**样本量**。并行派发天然是 A/B——同任务给
不同角色/prompt/模型，E4.1 的结局数据就是现成的对比实验。反过来，自进化给多 agent
解决"团队从哪来"：角色可生成（阶段 13.2）、prompt 可自改进（13.3）、工具可固化（13.4）。

## 三条防缠原则（"不越改越麻烦"的机制化答案）

越改越麻烦的根源从来不是代码多，是**子系统之间长出私拉乱接的电线**。三条原则，
每一条都把一类未来的复杂度挡在门外：

### 原则一：进化产物只有一种形态——声明式产物文件，加载只有一条通路

一切进化产物（技能 SKILL.md、角色 `subagents/<name>.json`、prompt overlay
`personas/<role>.overlay.md`、工具包 `tools/<name>/TOOL.json`、记忆条目）都是
`~/.pure/` 下的**声明式文件 + 版本化 manifest**。加载统一走启动扫描 → 按类型分发
到**既有的**注册接缝：

| 产物类型 | manifest | 落到的既有接缝 |
|---|---|---|
| 技能 | SKILL.md（已有） | `<skills>` prompt 注入 + 技能开关 |
| 子 agent 角色 | `subagents/<name>.json` | `DefaultSubagentRegistry.register()` |
| 角色 prompt 改进 | `personas/<role>.overlay.md` | `createSystemPrompt()` 合并点 |
| 工具 | `tools/<name>/TOOL.json` | `ToolRegistry.register()`（MCP 同款） |
| 经验/注意 | 记忆库条目（已有） | prompt layer 注入 |

**新增一种可进化物 = 新增一种 manifest 类型映射，不新增加载路径、不新增子系统间
调用。** manifest 带 `version` 字段，格式将来演化靠版本分支，不靠运行时猜。

### 原则二：观测单向，进化永不阻塞运行时

运行时只**写**观测（现在就是这么做的：promptObservability 记录、E4.1 派发结局），
进化层只**读**观测做归因。进化层的任何动作——出建议卡、生成草稿、跑评测——
全是异步 advisory：**运行时不知道进化层的存在**，进化层永远不挡运行时的路。
这条保证以后加任何进化回路（新建议、新自动准入）都不用碰运行时代码。

### 原则三：事件即接口

子系统之间用事件流说话（EngineEvent / SubagentActivity / FailurePolicyDecision 都是
先例），不直呼内部。新增协作能力 = 新增事件类型，既有消费者不动。已定稿和待设计的
几项全部落在这条上：暂停/续跑加 `paused`/`resumed` 事件（阶段 12 设计）；插话进子
agent 复用插话分类器 + SteerInjected 同款机制；接力流水线是委派参数的声明式扩展，
不是 agent 间私开 socket。

## 分期路线

```
一、阶段 12 暂停/续跑        —— 运行时手感（多 agent 的安全手柄）
二、插话通道进子 agent       —— 纠偏直达干活的人（小改动，事件原则的示范作）
三、阶段 13.2 角色生成       —— 团队可生长（设计已定稿）
四、6.4 MCP OAuth            —— 工具进口上锁配钥匙
五、接力流水线               —— agent 间协作面（需要设计：委派参数声明 + orchestrator 交接）
六、13.3 overlay → 13.1 → 团队可观测 → 13.4 —— 自生长 + 看得住
```

前两步是"运行时手感"，三四步是"团队 + 生态能力"，后两步是"自生长 + 看得住"。
每步独立提交可回滚，间隔跑一次 v5 评测基线防止进化伤回归。

## 反面清单（明确不做）

1. **不做 agent 间自由对话网**：任意 agent 互聊是组合爆炸，协作面收敛为"声明式
   接力 + 父汇总"两种。
2. **不做运行中热替换产物**：产物下轮/下会话生效，运行中的 agent 不换 prompt
   不换工具——可预期性优先。
3. **不做无度量的自动准入**（纪律 1 重申）：任何生成物没有评测或使用数据支撑就
   不转正；进化层一切自动行为可被总开关关掉。
4. **不私拉跨子系统直调**：想加能力先问"能不能是一个事件类型 / 一个 manifest
   类型"，能就不写新通路。
5. **不建 wasm 计算库**（2026-09-20 评估结论）：最重计算已在 ort-web wasm 上，
   其余为 DOM 密集或进程外置，无残留热点。

## 架构验收口径（比功能验收更重要的三条）

1. **加一种可进化产物的成本**：只写 manifest 映射 + 一个扫描目录 + 对应注册接缝
   复用，不碰运行时主循环——超过这个面就说明原则一被破坏了。
2. **加一条进化回路的成本**：只读观测 + 产建议/草稿，运行时零改动——碰到运行时
   就说明原则二被破坏了。
3. **回归红线**：v5 基线不倒退；全量测试绿；关掉进化总开关后行为与纯运行时逐字节
   一致。
